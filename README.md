# Донор-напарник

Backend приложения «Донор-напарник» — сервиса, который помогает донорам вести историю донаций, находить центры сдачи крови и получать информацию о донорстве.

Backend разработан на Python с использованием FastAPI и PostgreSQL.

## Технологии

- Python 3.14
- FastAPI
- SQLAlchemy
- PostgreSQL (Neon)
- Alembic
- Pydantic
- Uvicorn

## Возможности backend

Backend предоставляет API для работы с общедоступной информацией:

- Центры сдачи крови.
- Мероприятия.
- Информационные памятки.
- Матрица интервалов между видами донаций.
- Версии нормативных интервалов с учётом дат действия.

История донаций и персональные сведения пользователей на сервере не хранятся. Они обрабатываются локально на устройстве пользователя средствами frontend.

## Подключение к общей базе данных

В проекте используется одна общая база данных PostgreSQL, размещённая в Neon.

**Все участники команды подключаются к одной и той же базе данных.** Создавать собственные базы данных или аккаунты Neon для работы над проектом не требуется.

Строку подключения к общей базе предоставляет руководитель проекта.

Важно:
- Строка подключения содержит логин и пароль базы данных.
- Передавать её следует только лично участникам команды, которым необходим доступ.
- Нельзя публиковать её в GitHub, README, общих чатах или исходном коде.
- Необходимо использовать только предоставленные руководителем проекта реквизиты.

## Установка и запуск

### 1. Требования

Перед началом работы необходимо установить:

- Python 3.14 или совместимую версию.
- Git.

### 2. Получение проекта

Склонируйте репозиторий:

```powershell
git clone <URL_РЕПОЗИТОРИЯ>
```

Перейдите в папку backend:

```powershell
cd donor-helper/backend
```

### 3. Создание виртуального окружения

```powershell
python -m venv .venv
```

Активируйте виртуальное окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 4. Установка зависимостей

```powershell
python -m pip install -r requirements.txt
```

### 5. Настройка переменных окружения

Создайте файл `.env` на основе шаблона:

```powershell
Copy-Item .env.example .env
```

Заполните `.env`:

```env
DATABASE_URL=полученная_от_руководителя_строка_подключения

ADMIN_API_KEY=полученный_административный_ключ

FRONTEND_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://localhost:5500,http://127.0.0.1:5500
```

Описание переменных:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к общей базе Neon |
| `ADMIN_API_KEY` | Секретный ключ для административных операций |
| `FRONTEND_ORIGINS` | Разрешённые адреса frontend для CORS |

Обычным разработчикам, которым нужны только публичные GET-эндпоинты, административный ключ передавать не требуется. Получать его следует только тем участникам, которым разрешено выполнять административные операции.

**Никогда не загружайте `.env` в GitHub.**

### 6. Работа с миграциями

Все участники используют одну общую базу данных. Её структура уже должна быть подготовлена руководителем проекта.

Проверить текущую версию миграций:

```powershell
alembic current
```

Посмотреть последнюю доступную миграцию:

```powershell
alembic heads
```

**Важно:** не запускайте `alembic upgrade head` самостоятельно без согласования с руководителем проекта. Поскольку база общая, миграции должны применяться централизованно одним ответственным разработчиком.

Не создавайте собственные миграции без согласования и не редактируйте уже применённые миграции.

### 7. Запуск сервера

```powershell
python -m uvicorn app.main:app --reload
```

По умолчанию локальный сервер будет доступен по адресу:

`http://127.0.0.1:8000`

У каждого разработчика будет собственный локально запущенный экземпляр backend, но все экземпляры будут работать с общей базой Neon.

## Документация API

После запуска сервера доступны:

| Адрес | Назначение |
|---|---|
| `/docs` | Swagger UI |
| `/redoc` | Альтернативная документация API |
| `/openapi.json` | OpenAPI-схема |
| `/api/health` | Проверка состояния backend и подключения к БД |

## Основные API-эндпоинты

### Центры сдачи крови

Префикс: `/api/centers`

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/centers` | Получить список центров |
| GET | `/api/centers/{center_id}` | Получить центр по ID |
| POST | `/api/centers` | Создать центр |
| PUT | `/api/centers/{center_id}` | Обновить центр |
| DELETE | `/api/centers/{center_id}` | Удалить центр |

### Мероприятия

Префикс: `/api/events`

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/events` | Получить список мероприятий |
| GET | `/api/events/{event_id}` | Получить мероприятие |
| POST | `/api/events` | Создать мероприятие |
| PUT | `/api/events/{event_id}` | Обновить мероприятие |
| DELETE | `/api/events/{event_id}` | Удалить мероприятие |

### Информационные памятки

Префикс: `/api/rules`

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/rules` | Получить активные памятки |
| GET | `/api/rules/{rule_id}` | Получить памятку |
| POST | `/api/rules` | Создать памятку |
| PUT | `/api/rules/{rule_id}` | Обновить памятку |
| DELETE | `/api/rules/{rule_id}` | Удалить памятку |

### Интервалы между донациями

Префикс: `/api/donation-intervals`

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/donation-intervals/matrix` | Получить матрицу интервалов |
| POST | `/api/donation-intervals/matrix` | Добавить новую версию матрицы |

Для получения нормативной матрицы на определённую дату используется параметр `for_date`.

Пример:

```text
/api/donation-intervals/matrix?for_date=2027-01-15
```

Если дата не указана, используется текущая дата.

## Административный доступ

Операции создания, изменения и удаления данных защищены административным ключом.

Для выполнения таких запросов необходимо передать HTTP-заголовок:

```text
X-Admin-Key: <ADMIN_API_KEY>
```

Ключ хранится в `.env` и предоставляется только участникам, которым разрешено управление данными.

На текущем этапе административные операции выполняются через Swagger UI.

Не помещайте административный ключ в общедоступный JavaScript-код frontend.

## Принципы хранения данных

Backend хранит только общедоступную информацию, необходимую для функционирования приложения.

История донаций и персональные сведения пользователей обрабатываются локально на устройстве пользователя средствами frontend.

Передача истории донаций и личной информации на backend не предусмотрена.

## Работа с общей базой данных

Поскольку база данных общая для всей команды:

1. Не удаляйте и не изменяйте существующие записи без согласования.
2. Не применяйте миграции самостоятельно.
3. Не используйте реальные персональные данные пользователей.
4. Не публикуйте реквизиты подключения к Neon.
5. При обнаружении проблем с базой сообщайте руководителю проекта.

## Разработка

При внесении изменений в backend:

- Проверяйте входные данные через Pydantic.
- Используйте SQLAlchemy для взаимодействия с БД.
- Не храните секреты в исходном коде.
- Не добавляйте персональные данные пользователей в серверную базу.
- Согласовывайте изменения моделей и миграций с ответственным разработчиком.
- Обновляйте документацию при изменении API.
