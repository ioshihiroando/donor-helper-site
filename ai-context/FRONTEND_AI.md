# Инструкция ИИ-помощнику frontend

Перед работой обязательно прочитай `AGENTS.md`.

## Твоя роль

Помогать разрабатывать клиентскую часть PWA «Донор-напарник» на JavaScript и интегрировать её с уже существующим FastAPI backend. Backend не переписывай и не подменяй frontend-заглушками то, что уже доступно через API.

## Основные функции frontend MVP

1. Показывать список центров сдачи крови и подробности выбранного центра.
2. Показывать список мероприятий и их подробности.
3. Показывать общую информацию и памятки для доноров.
4. Получать матрицу интервалов между типами донаций и использовать её для расчётов в интерфейсе.
5. Позволять пользователю вести личный дневник донаций на своём устройстве.
6. Показывать ориентировочную дату следующей возможной донации и напоминания на основе локального дневника и актуальной матрицы интервалов.

Перед добавлением новых экранов или функций проверь, что они входят в MVP и согласованы командой.

## Разделение данных

### Загружать с backend

- центры;
- мероприятия;
- общие правила и памятки;
- матрицу интервалов и сведения о её периоде действия/источнике.

### Хранить локально на устройстве

- личную историю донаций;
- выбранные пользователем типы и даты донаций;
- локальные настройки напоминаний;
- пользовательские предпочтения интерфейса, если они нужны.

Не отправляй локальный дневник, даты личных донаций или сведения о здоровье на сервер. Не добавляй авторизацию и пользовательские аккаунты: в текущем MVP их нет.

Для локального хранения используй существующий в проекте механизм. Если его ещё нет, предложи простой слой работы с `localStorage`, отделённый от UI. Продумай обработку отсутствующих, повреждённых и устаревших данных. Не храни секреты в `localStorage`.

## Интеграция с API

Известные группы:

- `GET /api/health`;
- `GET /api/centers` и получение отдельного центра;
- `GET /api/events` и получение отдельного мероприятия;
- GET-маршруты `/api/rules`;
- `GET /api/donation-intervals/matrix` с возможным параметром `for_date`.

Точные пути и поля проверь по `/docs` запущенного backend или по `backend/app/schemas.py` и роутерам. Не угадывай структуру JSON и не дублируй серверные схемы вручную без проверки.

### Требования к API-клиенту

- Вынеси базовый URL API в одно место конфигурации.
- Вынеси сетевые запросы в отдельный модуль/слой, не смешивай `fetch` с компонентами или обработчиками UI повсюду.
- Обрабатывай состояния загрузки, пустой ответ, отсутствие сети, HTTP-ошибки и некорректный JSON.
- Не делай вид, что данные загружены, если запрос завершился ошибкой.
- Для общедоступных данных используй только публичные GET-маршруты.
- Не отправляй заголовок `X-Admin-Key` из браузера и не проси его у пользователя.
- Не включай персональные данные в query-параметры, URL, логи и сообщения об ошибках.

## Расчёты интервалов

Матрица содержит коды `whole_blood`, `rbc_1_unit`, `rbc_2_units`, `plasma`, `platelets`, `granulocytes`. Не зашивай интервалы в JavaScript как константы: источником значений должна быть матрица backend.

Вынеси вычисления в отдельные чистые функции, чтобы их можно было тестировать без UI. Учитывай дату действия версии матрицы. Перед реализацией проверь точный смысл поля `days`, правила выбора строки/столбца и формат ответа по backend-схеме. Не делай медицинских выводов и не обещай, что расчёт гарантирует допуск к донации: окончательное решение принимает медицинский персонал.

Если матрица недоступна или для даты нет подходящей версии, явно покажи, что расчёт временно недоступен. Не подставляй придуманные значения.

## PWA и UX

- Сначала изучи текущую структуру и используемые инструменты сборки.
- Не меняй фреймворк и способ сборки без необходимости.
- Интерфейс должен оставаться пригодным для мобильного экрана.
- При отсутствии интернета локальный дневник должен оставаться доступным; сетевые данные показывай с понятным состоянием недоступности.
- Не очищай локальные данные пользователя при обновлении приложения.
- Перед изменением формата локального хранилища продумай миграцию старых записей или безопасное сохранение совместимости.
- Не добавляй push-уведомления, геолокацию, карты или другие внешние сервисы, пока команда не согласовала их включение в MVP.
